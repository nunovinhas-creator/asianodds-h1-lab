# Prepared segmented store — NOT ACTIVATED

Reproduction: #158 shards only patterns and leaves prospective_settled/latest_events inside one manifest. A 500-entry synthetic settled collection exceeds its 256 KB manifest ceiling even when patterns is empty. The new store segments all top-level maps and lists, verifies each shard plus whole-state SHA-256, and retains compressed legacy bytes for exact reconstruction. Individual oversized entries fail closed. Existing production 2 MB/public 1.4 MB guards remain unchanged.

Local POSIX protocol: writers take an advisory flock and must supply expected_generation (None only for initial migration). Immutable generation members are exclusively created, flushed/fsynced and verified before atomic CURRENT replacement. A stale writer must reread and recompute rather than overwrite an intervening update. Readers take one atomic pointer snapshot and see a complete immutable generation. PREVIOUS enables explicit verified rollback with expected pointer SHA; corrupt CURRENT never causes silent fallback. Legacy export is exclusive/atomic and byte-exact. No cleanup deletes old generations.

Compatibility drill runs the existing discovery_timeline.build producer against legacy-loaded and segment-reconstructed states, compares outputs, and bounds the existing public JSON. Tests cover actual state bytes, oversized non-pattern metadata, two competing processes (one wins, one stale), concurrent readers, partial writes, pointer failure, interruption/resume, corruption of shards/manifests/compressed legacy, invalid rollback, symlinks, duplicate/nonfinite JSON, and exact recovery. These are offline proofs, not a productive migration.

## Activation proposal — separate authorization required

1. Inventory consumers with rg for discovery-state.json. lab_discoveries producer, validators/gates, tests, Pages/publication bundle and recovery tools must use one shared loader contract. Do not enable via an undocumented environment flag.
2. Freeze a normal published source commit; hash legacy state and monthly archives; preserve all existing FINAL scores. Build the first generation into an isolated prepared directory. Verify byte-exact legacy reconstruction and identical producer/public outputs. No productive writes in this PR.
3. Separate activation PR must wire the producer AND every reader, publication bundle/explicit git-add paths and deployment checks. Keep all members in one Git commit. Validate reachability from CURRENT/PREVIOUS, per-member limits and full-state hash before push. Remote Git concurrency needs expected-ref CAS and complete recomputation after a rejected push; local flock is NOT proof of distributed Git atomicity.
4. Initially keep the legacy source as a checked mirror while below 2 MB and compare both loaders. Record the source commit and generation in publication evidence. Do not independently update a pointer in Git/Pages before all immutable members exist. Later removal of the legacy mirror requires another explicit acceptance step and reader inventory.
5. Failure: abort publication and retain last complete commit. Recovery: verify PREVIOUS and archived source bytes; explicit pointer rollback with expected-pointer hash, create a new reviewed Git commit, then ordinary CI/publication. No forced push, automatic score downgrade or silent old-generation fallback. Test remote Git rejection/cancellation and workflow concurrency in the activation PR before enabling.

All productive imports, loader paths, workflows and state formats remain unchanged. This is a concrete prepared store and migration plan, not authorization to activate it. No H1/Telegram/strategy/FT certification changes.
